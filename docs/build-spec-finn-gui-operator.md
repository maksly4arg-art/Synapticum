# 1. Реальность зрения (отвечает на «видишь ли в реальном времени»)
НЕТ видео-потока — computer-use это дискретные СКРИНШОТЫ. Поэтому:
- Не «до/после каждого клика». План снимается ОДИН раз → Finn исполняет всю последовательность сам → одна проверка в конце (или ноль, если результат — факт: файл/символ на тикере).
- Руки батчить: давать Finn СЕРИЮ действий одним exec (не пинг-понг по клику).

# 2. ДВЕ СХЕМЫ ИСПОЛНЕНИЯ (делать обе — деградация-вверх, не «или-или»)
## A. Гибрид: глаза планировщика + руки Finn
- Планировщик (Builder через computer-use; или другой агент) ВИДИТ (скриншот/inspect/zoom) → строит ПЛАН (координаты/текст/клавиши) → «заводит» руки Finn → **Finn исполняет всю последовательность САМ** (osascript/cliclick) → возвращает РЕЗУЛЬТАТ ФАКТОМ (финальный скриншот/исход) → планировщик отдаёт текстом.
- Планировщик = восприятие+план+ignition, НЕ тугая петля по клику.
## B. Автономный: Finn сам всё
- Своя зрячая петля: Finn `screencapture` → qwen-зрение анализирует кадр → решает → клик (osascript/cliclick) → новый кадр → проверка → повтор. Полностью самоходный.
- Тяжелее: нужен agent-loop с подачей СКРИНШОТА обратно в контекст Finn (OpenClaw image-input). qwen-GUI-рассуждение слабее моего → A надёжнее, B автономнее. Где B не справился → подключается A (мои глаза).

# 3. ДВА ПУТИ ДОСТУПА (не «две кнопки», а две роли)
## 1) Finn = ИНСТРУМЕНТ для агентов (по умолчанию, без включений)
- Руки-оператор Finn = общий вызываемый инструмент, который ЛЮБОЙ агент (Builder, Jesse, Eva, …) дёргает по требованию, всегда доступен, никаких тумблеров. Governance: Junior-тир → агенты зовут САМИ без подтверждения юзера (Middle/Senior/Consilium — с подтверждением).
- Нужен чистый интерфейс «hands»: `click(x,y) / type(text) / key(code) / open(app) / screenshot() / exec(cmd)` — структурные действия, Finn исполняет. Кандидаты механизма: (а) **MCP «computer-control» сервер, подключённый к Finn в OpenClaw** (тогда у Finn НАТИВНЫЕ инструменты click/type/screenshot, а не сырой shell) — чище всего, годится и для A, и для B; (б) A2A-эндпоинт hands; (в) прямые `openclaw agent` вызовы со структурным протоколом.
## 2) Finn = turnkey-АГЕНТ юзера
- Finn как личный оператор: юзер говорит «сделай X на компе» → Finn ведёт end-to-end (схема B, с откатом на A). Это «мой агент под ключ, который это умеет».
